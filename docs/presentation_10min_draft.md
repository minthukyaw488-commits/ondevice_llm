## 슬라이드 2 — 기존 해결책의 한계 (Why existing solutions fall short)

**🇰🇷 화면 내용**
- **A. 인력 기반 서비스** (노인맞춤돌봄, 요양보호사)
  - 돌봄 인력 부족이 구조적 고착 — 2043년까지 최대 **99만 명** 추가 필요 전망
  - 전담사회복지사 고용 불안정·잦은 이직 → 서비스 질 저하, 도농 격차
  - → 인력만으로는 근본 해결 불가, **기술적 보완 필요**
- **B. 기존 AI 돌봄** (KT 케어콜, 네이버 클로바 등)
  - **클라우드 기반** → 개인정보 보안 이슈
  - 범용 스크립트 → **대전 지역 맞춤 정보 미반영**
  - 단순 '말벗' 수준, 실질적 복지 안내 부족
- **C. 텍스트 웹/앱** (복지로 등)
  - 텍스트 위주 UI → 디지털 문해력 낮은 고령층 **접근성 낮음**

**🇲🇲 မြန်မာ မှတ်စု**
- ရှိပြီးသား ဖြေရှင်းချက် ၃ မျိုးရဲ့ **အားနည်းချက်** ကို ပြ → ကျွန်တော်တို့ project လိုအပ်ကြောင်း ခိုင်မာစေ။
- **A. လူအားနဲ့ ဝန်ဆောင်မှု** — care 인력 ပြတ်လပ် (2043 အထိ 99만 လို)၊ လူ ချည်းနဲ့ မဖြေရှင်းနိုင်။
- **B. Cloud AI (KT/Naver)** — cloud မို့ privacy ပြဿနာ + 대전 특화 မဟုတ် + 말벗 သက်သက်။
- **C. Text web/app (복지로)** — စာ များ၊ သက်ကြီးတွေ သုံးရ ခက်။
- ⭐ ဒီ ၃ ချက်က ကျွန်တော်တို့ရဲ့ ကွာခြားချက် ၃ ခု (**on-device / 지역맞춤 / 음성·대화**) နဲ့ တိုက်ရိုက် ဆန့်ကျင်ဘက် — slide 3 မှာ ချိတ်။
- 근거 검색: KDI, 복지타임즈 "요양보호사 인력 부족"; "AI 케어콜 한계"; 복지로 UI 스크린샷.

## 슬라이드 3 — 프로젝트 개요 (Overview)

**🇰🇷 화면 내용**
- **시스템명:** 온디바이스 LLM 기반 독거노인 복지정보 안내 및 이상징후 감지 시스템
- **핵심 기능 2가지**
  - (a) **Local LLM + RAG** 로 대전 복지 정보 **대화형 안내**
  - (b) **대화 패턴 기반 이상징후 감지** → 사회복지사 알림
- **기술적 차별점:** **On-device(비클라우드)** → 개인정보 보안 강화, 오프라인 작동 가능
- **타겟 사용자:** 대전 독거노인, 그 가족, 사회복지사
- **기대효과:** 응급상황 조기 발견 · 복지 정보 접근성 향상

**🇲🇲 မြန်မာ မှတ်စု**
- ကျွန်တော်တို့ system ကို **တစ်မျက်နှာနဲ့** ရှင်းပြတဲ့ slide။
- Function ၂ ခု: (a) 복지 Q&A (Local LLM+RAG), (b) 이상징후 감지 → 사회복지사 알림။
- ⭐ ကွာခြားချက်: **On-device** = cloud မဟုတ် → privacy လုံခြုံ + offline ရ။
- Target: 독거노인 + 가족 + 사회복지사။
- **Diagram idea:** input → [복지안내] + [이상감지] → 어르신 답변 + 복지사 알림 (icon ၂ ခွ)။

## 슬라이드 4 — 시스템 아키텍처 (Architecture)

**🇰🇷 화면 내용**
- **한 줄:** 하나의 질문 → 복지 안내 + 이상신호, 모두 기기 안에서.
- **흐름도:**
  1. 입력 (음성/문자) → **STT (Whisper, 로컬)**
  2. **의도 라우팅** — 인사·잡담 vs 복지 질문
  3. **Layer 1 · RAG:** 정제 → 섹션 청킹 → bge-m3 임베딩 → ChromaDB 후보 10개
     → **cross-encoder 재랭킹** → **관련성 게이트** → 상위 3개
  4. **로컬 LLM (EXAONE 3.5 2.4B)** — 검색 근거로만 한국어 답변
  5. **Layer 2 · 이상신호 감지** — 증상 반복 + 감정 + 개인 baseline
  6. 출력: 어르신 답변 **+** (이상 시) 사회복지사 알림
- **강조:** 전 과정 **로컬** — 대화는 기기·가정 네트워크를 벗어나지 않음

**🇲🇲 မြန်မာ မှတ်စု**
- ဒီ slide က **technical flow** — ဒါပေမဲ့ professor က "deploy နည်း" မကြည့်ချင်လို့၊ **"input → ဘာဖြစ်သွားလဲ → output"** ရိုးရိုး diagram ပဲ ပြ၊ 용어 များများ မထည့်။
- အဓိက ၂ လွှာ: **Layer 1 = 복지안내 (RAG)**, **Layer 2 = 이상신호**။
- ⭐ အောက်ခြေမှာ ကြီးကြီး: **"모든 처리는 로컬 · 대화는 밖으로 안 나감"** — privacy က ကျွန်တော်တို့ရဲ့ အားသာချက်။
- **Diagram idea:** အပေါ်→အောက် flow box တွေ၊ Layer 1/Layer 2 ကို ဘေးတိုက် ၂ ခွ။

## 슬라이드 5 — 핵심 기능 데모 (Core Demo)

**🇰🇷 화면 내용**
- **데모 A · 복지 Q&A** (실제 화면 캡처)
  - 예) "기초연금은 어떻게 신청하나요?" → 문서 근거 기반 정확한 안내
  - 범위 밖 질문은 **안전하게 거절** ("주민센터에 문의하세요")
- **데모 B · 이상신호 감지**
  - 대화 예) "무릎이 아파요" 반복 + "외롭고 우울해요" → **이상신호 감지 → 복지사 알림 요약**

- **성능 (자체 200문항 평가):** 정답률 **92%**, 재랭킹 적용 시 **+14%p**

**🇲🇲 မြန်မာ မှတ်စု**
- ဒီ slide = **တကယ် အလုပ်လုပ်တာ ပြ** (screenshot ၂ ရွက် အကောင်းဆုံး)။
- Demo A: 복지 Q&A — မှန်ကန်တဲ့ အဖြေ + 범위 밖 ဆို safe 거절။
- Demo B: 이상신호 — အနာ ထပ်ခါ ပြော + စိတ်ဓာတ်ကျ → 복지사 알림။
- 数字: **3,455 청크**, 정답률 **92%**, reranking **+14%p** (professor: data well-managed ကို ဒီမှာ ပြ)။
- ⭐ Screenshot: app.py ရဲ့ 복지 답변 တစ်ရွက် + 이상신호 알림 တစ်ရွက် ကြိုဖမ်းထားပါ။

## 슬라이드 6 — 지역사회 연계 방안 (Community Linkage)

**🇰🇷 화면 내용**
- **누구와 연결되나:**
  - **주민센터·구청 노인복지과** — 신청·상담으로 연결
  - **사회복지사·생활지원사** — 이상신호 알림 → 방문·전화 대응
  - **치매안심센터·보건소·노인복지관** — 서비스 안내 연계
- **어떻게 운영하나:**
  - 경로당·복지관에 **허브(태블릿/미니PC)** 배치, 어르신은 같은 WiFi로 접속
  - 지역 복지 데이터는 구청 협조로 **주기적 갱신**
- **왜 지속가능한가:** 클라우드 비용 없음 · 개인정보 부담 낮음 → 지자체가 운영 부담 적게 도입

**🇲🇲 မြန်မာ မှတ်စု**
- ဒီ slide က professor အတွက် အရေးကြီး — **"တကယ့် လူမှုအကျိုးပြု project"** ဆိုတာ ပြ (မြေပြင် ချိတ်ဆက်မှု)။
- ဘယ်သူတွေနဲ့ ချိတ်: 주민센터/구청, 사회복지사, 치매안심센터/보건소/복지관။
- ဘယ်လို run: 경로당/복지관 မှာ **hub (tablet)** ထား → 어르신 WiFi နဲ့ သုံး။ Data ကို 구청 နဲ့ ပုံမှန် update။
- ⭐ ရေရှည်တည်တံ့: cloud စရိတ် မရှိ + privacy ဝန်ထုပ် နည်း → 지자체 လွယ်လွယ် လက်ခံ။
- **Diagram idea:** အလယ်မှာ system၊ ပတ်ပတ်လည်မှာ 주민센터/복지사/보건소/경로당 icon (연결 지도)။

## 슬라이드 9 — Limitations (한계·정직한 평가)

**🇰🇷 화면 내용**
- **평가셋 한계:** 자체 제작(held-out 미구성)·키워드 기반 채점 → **사람/LLM 평가**로 보강 예정
- **문서 형식:** `.hwp` 미지원 → 현재 PDF로 대체 (향후 지원 과제)
- **현장 실증 미완:** 실제 어르신 대상 파일럿 필요
